# Java 注释规范

适用于 Java 源码、Javadoc、Spring Boot / Spring MVC、Service、Repository、领域模型等。遵循主文件 `SKILL.md` 的简体中文默认规则与只修改注释的边界。

## 1. 注释形式与选择

- 对外暴露的类、接口、公共方法、值得记录约束的字段使用 Javadoc：`/** ... */`。
- 局部业务原因或实现取舍，使用 `//`；较长的解释可使用紧邻代码的块注释 `/* ... */`。
- 不要求对所有 `public` 元素机械补齐模板；优先说明实际契约、边界及使用者无法从签名看出的信息。
- 避免固定注释头（作者、创建日期、修改时间）；版本历史应由版本控制系统负责。
- 包级文档仅在真正需要时使用 `package-info.java`；不要无目标创建文件。

## 2. 类型与 API 文档

### 类、接口、枚举、record

- 描述单一职责、业务意义、使用约束；需要时说明线程安全、生命周期、可变性。
- 接口重点说明契约、前置条件与可观察行为；实现类只补充与接口不同的重要实现细节。
- 枚举重点说明状态/代码的领域含义和非法转换约束，不逐个复制枚举名字。
- `record` 组件、值对象只在字段名称和类型无法表达含义时增加说明。

### 方法

- 第一段以中文概括业务意图或调用契约，不写“该方法用于调用某方法”。
- `@param`：解释非显然的含义、单位、允许范围、空值语义；不要仅重复参数名称。
- `@return`：说明结果语义，尤其是布尔值、`null`、空集合、`Optional`、状态码等；不必重复明显的返回类型。
- `@throws` / `@exception`：只为确实可能抛出的、有调用方处理价值的异常说明触发条件；不杜撰异常。
- 泛型参数按需使用 `@param <T>`；覆写方法若继承文档已准确，无需复制，可保留或使用 `{@inheritDoc}`。
- `@deprecated` 只在真实废弃的 API 上使用，注明替代方案或迁移条件；保留其与 `@Deprecated` 的一致性。
- 保留 Javadoc 标签原文，标签后的描述使用简体中文；必要时使用 `{@code ...}`、`{@link ...}` 准确指向代码元素。

## 3. 业务与实现注释

重点解释：

- 金额计算、精度与舍入策略的业务依据；订单、审批、退款、库存等状态转换的前置条件。
- 幂等条件、重试边界、并发冲突处理、空值/缺省值与历史兼容行为。
- 不明显的算法复杂度、缓存一致性或性能权衡；需要时解释“为什么不采用简单方案”。
- 异常吞掉或转换的原因（若从上下文可证实），不可把可疑行为美化为业务要求。

注释应贴近关键判断；常规变量赋值、日志语句、简单循环不加“赋值”“打印日志”“遍历”类注释。

## 4. Spring / 并发 / 持久化场景

- Controller：当请求契约不明显时说明鉴权/幂等/输入边界，避免简单复述 URL 与注解。
- Service：聚焦跨步骤业务规则、事务边界及重要的失败后果，不写“调用 Mapper 查询数据”。
- Repository / ORM：仅对查询的非直观过滤条件、锁语义、N+1 防护或排序依赖作说明；不解释显而易见的 CRUD。
- `@Transactional`：只根据真实注解配置和调用关系说明事务语义，不能凭猜测承诺回滚范围。
- `synchronized`、锁、原子类、异步任务：解释被保护的不变量、锁顺序或可见性要求（前提是代码证明如此）。
- Bean 生命周期、代理、自调用与缓存注解相关约束，如影响行为且上下文明确，应指出。

## 5. 避免的问题

- 不将 Javadoc 当作冗长的逐行执行流程。
- 不补写与签名、注解、校验规则矛盾的参数或异常说明。
- 不在未验证时断言“线程安全”“无副作用”“一定回滚”“O(1)”等。
- 不修改 `@Generated` 相关标记、生成代码标识、许可证、工具控制注释。
- 不为无特殊语义的 Getter/Setter、构造器、`toString`、`equals` 机械添加注释。

## 6. 示例与自检

以下只是演示如何描述已知规则，不代表其他项目中同名字段具有相同业务含义。

### 方法级 Javadoc

```java
/**
 * 判断订单是否允许取消。
 *
 * <p>已支付订单必须先满足退款条件，以避免取消后出现资金状态不一致。
 *
 * @param order 待取消的订单
 * @return {@code true} 表示允许取消；{@code false} 表示不允许取消
 */
public boolean canCancel(Order order) {
    // 已支付订单进入取消流程前，需要先满足退款条件。
    if (order.isPaid()) {
        return checkRefundEligibility(order);
    }
    return order.isPending();
}
```

注意：参数空值限制、具体异常等约束只在源码或契约实际保证时才可填写；否则省略，不要推测。

### 复杂分支

```java
// 先更新版本号再扣减库存，利用受影响行数判断并发修改是否成功。
int updated = stockMapper.tryDeduct(productId, quantity, expectedVersion);
if (updated == 0) {
    throw new ConcurrentModificationException("库存已发生变化");
}
```

只有当 `tryDeduct` 确实实现了版本条件更新时，才可以使用上面这条解释。

### Java 自检

- Javadoc 标签拼写和位置是否正确，是否与真实签名、异常和注解吻合？
- 是否存在没有代码依据的业务规则或 API 承诺？
- 是否保留接口继承文档，避免覆写类中重复描述？
- 是否未改动任何 Java 代码、导入、注解或构建指令？

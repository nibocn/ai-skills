# Git 中文提交 Skill

帮助用户分析代码变更，生成简洁、准确的中文提交信息，并在用户明确授权后执行本地提交。

## 核心原则

**不擅自提交**：生成提交信息 ≠ 执行提交。只有用户明确表达提交意图（"帮我提交"、"提交这些改动"、"commit 一下"），才执行 `git commit`。

**不推送远程**：任何情况下都不执行 `git push`、`git push origin` 等推送命令。提交只做本地 commit。

**信息简洁准确**：提交信息说清楚"改了什么、为什么改"，不堆砌无意义的套话，不啰嗦重复。

---

## 第一步：分析变更

执行以下命令了解当前仓库状态：

```bash
git status
git diff --staged    # 已暂存的变更
git diff             # 未暂存的变更
```

如果用户没有指定变更范围，先展示 `git status` 结果，让用户确认哪些文件需要提交。**不要自动执行 `git add`。**

---

## 第二步：生成提交信息

### 格式规范

```
<类型>(<范围>): <简短描述>

[可选正文：当变更复杂或原因不明显时补充]
```

- **标题行**：不超过 72 个字符，中文描述，末尾不加句号
- **正文**（可选）：解释"为什么"而不是"做了什么"，代码已经说明了做了什么

### 类型前缀（保留英文，其余中文）

| 类型 | 含义 |
|------|------|
| `feat` | 新增功能 |
| `fix` | 修复 Bug |
| `refactor` | 重构（不影响功能） |
| `style` | 代码格式、空格等（不影响逻辑） |
| `docs` | 文档更新 |
| `test` | 测试相关 |
| `chore` | 构建配置、依赖更新等杂项 |
| `perf` | 性能优化 |
| `revert` | 回滚提交 |

### 范围（scope）

根据实际改动模块填写，如：`user`、`auth`、`order`、`api`、`db`、`config` 等。如果变更跨多个模块或无明确范围，可省略 scope。

### 描述写法要点

- 说明**具体问题**，不写泛泛的描述
- ❌ 差：`fix(user): 修复用户模块问题`
- ✅ 好：`fix(user): 修复用户注册时手机号重复校验失败的问题`
- ❌ 差：`feat(order): 添加订单功能`
- ✅ 好：`feat(order): 新增订单超时自动取消逻辑`

---

## 第三步：展示提交信息

生成后，以如下格式展示给用户确认：

```
建议的提交信息：

fix(auth): 修复 JWT token 过期后未清除本地缓存导致重复请求的问题

是否使用此信息提交？（或告诉我需要调整的地方）
```

如果有多个候选角度，可以给出 2 条供用户选择，但不要超过 2 条。

---

## 第四步：执行提交（仅在用户明确确认后）

用户确认后执行：

```bash
git commit -m "<提交信息>"
```

如果提交信息有正文部分：

```bash
git commit -m "<标题>" -m "<正文>"
```

提交成功后，展示 commit hash 和简要结果，并明确告知用户：**本次为本地提交，未推送到远程仓库。**

如果 `git commit` 因 GPG 签名、pinentry、TTY 不可用等原因失败，必须先向用户说明签名失败原因，并询问用户选择：由用户在本机终端手动完成签名提交，或明确允许使用 `--no-gpg-sign` 后再重试。禁止自动追加 `--no-gpg-sign` 重试。

---

## 判断是否执行提交的参考

| 用户说的话 | 应该做什么 |
|-----------|-----------|
| "帮我生成一个 commit message" | 只生成信息，不提交 |
| "这次改动怎么写提交信息" | 只生成信息，不提交 |
| "帮我提交一下" | 生成信息 → 确认 → 提交 |
| "commit 这些改动" | 生成信息 → 确认 → 提交 |
| "直接提交吧" | 生成信息 → 提交（可跳过二次确认） |
| "写个 commit" | 语义模糊，只生成信息，询问是否需要提交 |

---

## 禁止行为

- ❌ 不执行 `git push` / `git push origin <branch>` 等任何推送命令
- ❌ 不在用户未明确要求时自动执行 `git commit`
- ❌ 不自动执行 `git add`（暂存区管理由用户负责）
- ❌ 提交信息中不使用英文描述（类型前缀除外）
- ❌ 不生成套话式提交信息（如"优化了相关逻辑"、"修复了一些问题"）
- ❌ `git commit` 因 GPG 签名、pinentry、TTY 不可用等原因失败时，不自动使用 `--no-gpg-sign` 重试；必须先询问用户
